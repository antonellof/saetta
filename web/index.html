Saetta: a local coding agent with the model built in.

Written in C for Apple Silicon Macs. Qwen3.8 runs in the same process, with no server in between. Tools, sessions and terminal UI come from pi, and the engine also serves Claude Code, opencode and pi itself.

curl -fsSL https://saetta.dev/install.sh | sh
saetta start code
curl -fsSL https://saetta.dev/install.sh | sh
saetta start claude      # or: saetta start pi, saetta start opencode
git clone https://github.com/antonellof/saetta.git && cd saetta
make && ./build/bin/saetta start code

saetta start code picks the model that fits this Mac, downloads it and opens the agent on it.

The model runs inside the agent

saetta start code picks the model that fits this Mac, downloads it if needed and loads it into the agent's own process. There is no server and no HTTP between the agent and the model. A lightning bolt turns in the terminal while the weights load.

/monitor opens the engine's live view inside the agent: speed, GPU load and memory, how much of each prompt came from the cache, how far speculation runs ahead, and every recent request.

Pick and download models

/model lists every saetta pack: the ones already on this Mac, the ones to download with their size, and the ones too big for its memory, greyed out. A downloaded pack loads in the same process; another is downloaded first, after the free disk is shown.

The same list holds the OpenAI-compatible servers from pi's models.json, a remote saetta among them, and its last entry adds a new one.

Resume, branch and export sessions

Sessions are pi's JSONL files in pi's folder, so a session started in pi continues here, and the other way round. /resume lists this folder's sessions by name and age. /tree shows every branch of a session and moves to any earlier message to continue from there.

/export writes the session as one HTML page, with the tree in a sidebar and tool output and diffs inline. /share uploads it as a secret GitHub gist.

Context from AGENTS.md and skills

At start the agent lists what it put in the context: the AGENTS.md and CLAUDE.md files of your home folder and the project, and the skills it found. The prompt holds each skill's name and description; its instructions load when the model needs them, or when you call it with /skill:name.

Steer or follow up while it works

You can type while the agent runs. Enter queues a steering message, delivered after the current tool call; Alt+Enter queues a follow-up, sent when the run ends. Both wait above the editor, and Alt+Up brings them back to edit.

See what each tool did

Edits show as diffs with line numbers. Bash output streams in while the command runs and is cut to its last lines; Ctrl+O expands every tool's output. Reads, writes, grep, find and ls have their own views.

MCP servers

Servers from pi's mcp.json connect over stdio or Streamable HTTP, and their tools are offered to the model. /mcp shows each server's state and tools, reconnects it, turns it off everywhere or in one project, and changes how its tools are exposed.

Print and JSON modes for scripts

saetta code -p answers one prompt and exits, and reads what is piped into it, so it works in shell scripts and CI. --mode json prints pi's event stream, one JSON object per line.

The same setup as pi

Saetta Code, the agent in the saetta binary, is a port of the pi coding agent 1.5.2 (MIT): one 2.3 MB binary with no Node.js and no Python. It reads and writes pi's settings.json, models.json, trust.json and mcp.json in ~/.pi/agent. Its requests and session files match pi's byte for byte on 54 recorded scenarios, and its screens are compared with pi's on 61.

run it
# the model inside the agent
saetta start code
# the same with a chosen pack
saetta code --pack coder
# continue this folder's last session (pi's too)
saetta code -c
scripts and CI
# print mode, as pi -p
saetta code -p "fix the failing test"
# pi's JSON event stream
saetta code --mode json -p "list the TODOs"

Fine-tunes and adapters

GGUF fine-tunes of Qwen3.8-27B convert into packs, their MTP layer kept as the draft head. PEFT LoRA adapters apply per request, with vLLM's flags.

Every model is verified against a numpy reference at every layer before a change lands, and every speed number comes from a recorded benchmark.

        FAQ
        
Questions

        

          
Does Saetta work with my pi sessions and settings?
Yes. It reads and writes pi's settings.json, models.json, trust.json and mcp.json in ~/.pi/agent, and keeps its session files in the same folder and format as pi 1.5.2, so either one continues a session the other started. It also reads AGENTS.md and CLAUDE.md files, skills and prompt files as pi does. pi's TypeScript extensions are not supported.

          
Can Saetta use a model other than the local one?
Yes. By default the model runs inside the agent. It can also use a running Saetta server, or any OpenAI-compatible chat completions server listed in pi's models.json. /model switches between them and adds new ones.

          
Does Saetta support MCP servers?
Yes. It reads pi's mcp.json (global, or .pi/mcp.json in a trusted project) and connects to stdio and Streamable HTTP servers. Their tools are offered to the model, and /mcp manages the servers.

          
Can I use Claude Code with a local model?
Yes. saetta start claude runs Claude Code against Saetta's Anthropic-compatible API on your own Mac, without editing your Claude Code configuration. pi and opencode work the same way with saetta start pi and saetta start opencode.

          
Which Mac do I need to run a coding LLM locally?
Any Apple Silicon Mac (M1 or later) with 32 GB of memory or more and macOS 27.2. 32 GB runs Qwen3.8-27B in 4-bit, 36 GB the 27B TURBO or Fable-5 coding fine-tunes, 48 GB the Coder390 fine-tune, 96 GB Qwen3.8-Flash-Next Coder and 128 GB the full Flash-Next. Saetta picks the one that fits.

          
Does my code leave my machine?
No. The model runs on your Mac, inside the agent or in a server that listens only on 127.0.0.1, so prompts and code stay local. The network is used to download the model weights from Hugging Face, for the agent's update check at start (SAETTA_SKIP_VERSION_CHECK=1 turns it off), and for what you ask for: /share, a remote model or an MCP server you configure.

          
Is Saetta free?
Yes. Saetta is open source under the MIT license. The models keep their own licenses: Qwen3.8-27B and its TURBO, Coder390 and Fable-5 fine-tunes are Apache-2.0, Qwen3.8-Flash-Next uses the Qwen Community License.

          
How fast is it?
On an M5 Max with 128 GB, Qwen3.8-Flash-Next reads prompts at 1,600 to 1,950 tokens per second and answers at 66 to 85. Earlier chips run the same kernels on their GPU cores and are slower; they are not yet measured.

          
Which models does it run?
Qwen3.8-Flash-Next (the pruned Coder variant and the full model) and Qwen3.8-27B in 4-bit and 8-bit, with LoRA adapters and the TURBO, Coder390 and Fable-5 coding fine-tunes. Any Qwen3.8-27B GGUF can be converted with saetta import.
