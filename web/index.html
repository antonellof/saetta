Saetta Code: a coding agent with the model inside it.

Saetta Code is a local coding agent for Apple Silicon Macs. It is written in C, ships inside the saetta binary, and runs Qwen3.8 in its own process, with no server and no HTTP in between. It is a port of pi, with pi's tools, sessions and terminal UI. The same engine serves Claude Code, pi and opencode.

install, then start Saetta Code
curl -fsSL https://saetta.dev/install.sh | sh
saetta start code

saetta start code picks the model that fits this Mac, downloads it and opens the agent on it.

What Saetta Code does

A port of the pi coding agent 1.5.2 (MIT) in C, built into saetta. One 2.3 MB binary, no Node.js, no Python.

Runs the model itself

The engine loads inside the agent. saetta start code picks the model that fits this Mac, downloads it if needed and opens the agent; a 3D lightning loader is drawn inline while it loads.

/model switches between downloaded packs in process, downloads new ones from the list, and adds OpenAI-compatible models. /monitor shows the engine's live stats inside the agent.

MCP servers

Servers from pi's mcp.json, over stdio or Streamable HTTP. Their tools are offered to the model and /mcp manages them. OAuth sign-in is not supported yet.

run it
# the model inside Saetta Code
saetta start code
# the same with a chosen pack
saetta code --pack coder
# continue this folder's last session (pi's too)
saetta code -c
scripts and CI
# print mode, as pi -p
saetta code -p "fix the failing test"
# pi's JSON event stream
saetta code --mode json -p "list the TODOs"

Also: /settings, /thinking, /scoped-models, /hotkeys, /copy, /name, /session, /trust, /reload, /changelog, /skill:name, and an update check at start. Not supported: pi's TypeScript extensions and packages, image input.

Fits the Mac you have

Packs that cannot run are refused before they load, and the context is sized to the memory left. The M5's neural accelerators read prompts fastest; earlier chips run the same kernels.

Reads only what is new

Follow-up turns and new sessions reuse what the engine already read, so agents answer in a fraction of a second instead of re-reading the conversation.

Guesses ahead

Speculative decoding with each model's own draft head, plus prompt lookup for code that repeats what is already in context. Same output as plain decoding.

Fine-tunes and adapters

GGUF fine-tunes of Qwen3.8-27B convert into packs, their MTP layer kept as the draft head. PEFT LoRA adapters apply per request, with vLLM's flags.

layers       numpy oracle, every layer
logits       max rel err 6.7e-7

Checked, layer by layer

Every model is verified against a numpy reference at every layer before a change lands, and every speed number comes from a recorded benchmark.

        FAQ
        
Questions

        

          
Does Saetta Code work with my pi sessions and settings?
Yes. Saetta Code reads and writes pi's settings.json, models.json, trust.json and mcp.json in ~/.pi/agent, and its session files in the same folder and format as pi 1.5.2, so pi and Saetta Code continue each other's sessions. It also reads AGENTS.md and CLAUDE.md files, skills and prompt files as pi does. pi's TypeScript extensions are not supported.

          
Can Saetta Code use a model other than the local one?
Yes. By default the model runs inside Saetta Code. It can also use a running Saetta server, or any OpenAI-compatible chat completions server listed in pi's models.json. /model switches between them and adds new ones.

          
Does Saetta Code support MCP servers?
Yes. It reads pi's mcp.json (global, or .pi/mcp.json in a trusted project) and connects to stdio and Streamable HTTP servers. Their tools are offered to the model, and /mcp manages the servers. OAuth sign-in is not supported yet.

          
Can I use Claude Code with a local model?
Yes. saetta start claude runs Claude Code against Saetta's Anthropic-compatible API on your own Mac, without editing your Claude Code configuration. pi and opencode work the same way with saetta start pi and saetta start opencode.

          
Which Mac do I need to run a coding LLM locally?
Any Apple Silicon Mac (M1 or later) with 32 GB of memory or more and macOS 27.2. 32 GB runs Qwen3.8-27B in 4-bit, 36 GB the 27B TURBO or Fable-5 coding fine-tunes, 48 GB the Coder390 fine-tune, 96 GB Qwen3.8-Flash-Next Coder and 128 GB the full Flash-Next. Saetta picks the one that fits.

          
Does my code leave my machine?
No. The model runs on your Mac, inside Saetta Code or in a server that listens only on 127.0.0.1, so prompts and code stay local. The network is used to download the model weights from Hugging Face, for Saetta Code's update check at start (SAETTA_SKIP_VERSION_CHECK=1 turns it off), and for what you ask for: /share, a remote model or an MCP server you configure.

          
Is Saetta free?
Yes. Saetta and Saetta Code are open source under the MIT license. The models keep their own licenses: Qwen3.8-27B and its TURBO, Coder390 and Fable-5 fine-tunes are Apache-2.0, Qwen3.8-Flash-Next uses the Qwen Community License.

          
How fast is it?
On an M5 Max with 128 GB, Qwen3.8-Flash-Next reads prompts at 1,600 to 1,950 tokens per second and answers at 66 to 85. Earlier chips run the same kernels on their GPU cores and are slower; they are not yet measured.

          
Which models does it run?
Qwen3.8-Flash-Next (the pruned Coder variant and the full model) and Qwen3.8-27B in 4-bit and 8-bit, with LoRA adapters and the TURBO, Coder390 and Fable-5 coding fine-tunes. Any Qwen3.8-27B GGUF can be converted with saetta import.
